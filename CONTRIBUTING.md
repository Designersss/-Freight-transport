# Правила разработки

Рабочий процесс: Issue → ветка и Draft PR → реализация и Quick Checks → Ready for review и полный CI → ручная приёмка → merge. Следующий этап начинается только после приёмки текущего. Главный Issue #1; текущий #4 (RD-03). См. обязательные правила в [AGENTS.md](AGENTS.md) и обязательный для каждой задачи [movaro-code-style](.agents/skills/movaro-code-style/SKILL.md).

- Для каждой задачи отдельная ветка; для RD-01 feat/02-monorepo-init.
- Сначала изучить официальные API закреплённых версий, затем реализация. В PR приводить ссылки и обоснование архитектурных решений.
- TypeScript strict; SOLID, KISS, DRY; не создавать пустые абстракции.
- Все бизнес-операции через единый API. Серверные проверки прав, транзакции, изоляция компаний, аудит. Не дублировать бизнес-логику в клиентах.
- Пользовательские строки локализуются RU/EN. UI общий, shadcn/ui, Manrope, кобальтовый акцент, тёмная тема по умолчанию, светлая тема. Проверка реальных страниц в браузере по согласованному стилю.
- Только открытые бесплатные зависимости без обязательных облачных сервисов; проверка лицензий и совместимости, точные версии и lockfile.
- Тесты должны проверять реальные сценарии. Никаких production-заглушек и фиктивных данных. Проверки конкурентности и безопасности обязательны там, где применимы.
- Открытые вопросы ТЗ согласуются до реализации. Документация и Issues на русском; код и идентификаторы на английском.
- Не публиковать внутренние материалы и секреты. Не включать монетизацию без работоспособного механизма оплаты.

## Приёмка

PR ссылается на Issue, описывает изменения, результаты тестов и ограничения. Полный CI (`quality`) должен пройти на актуальной версии до ручной приёмки и merge; после исправлений вернуть PR в Draft и повторить Ready for review. Quick Checks не заменяет полный CI. Подробнее — раздел «CI по контрольным точкам» в AGENTS.md. Ручная приёмка обязательна. Не объединять PR автоматически. Настройка обязательных проверок ветки main выполняется владельцем репозитория после появления проверок CI.
