Статус: пятый срез рефакторинга RD-04, PR #24. Цель — ускорение обратной связи без потери проверяемых требований. Не меняем бизнес-логику, стек, зависимости, branch protection и обязательную ручную приёмку.

## Распределение проверок

- Unit: Vitest 4.1.12 / node:test — правила пароля, даты, username, IP, file policy, mapping, DTO, чистые вычисления. Дешёвые edge cases остаются.
- Contract/HTTP: Nest/Fastify inject, точный публичный allowlist, реальные коды, DTO, cookie/Origin, Orval drift. Публичный контракт проверяем в итоговом документе, а не независимыми дублирующими списками.
- Integration: PostgreSQL 17/Prisma 6.19.0, pg-boss, SeaweedFS 4.51, Mailpit, Better Auth 1.7.28, 18 compat files. Реальные constraints, транзакции, конкурентность, revoke, replay, права, cleanup и отказ внешней системы остаются обязательными.
- Controlled browser: Playwright 1.60.0 + axe, UI состояния с управляемыми ответами, темы/локали/viewport и accessibility. Не считать его реальным backend E2E.
- Real E2E: signup → email → proof → login → role cabinet → settings/logout, отдельный Admin, ключевые переходы credential/session. Не проходить все комбинации серверной валидации через браузер.
- Stack smoke: реальные процессы, зависимости, запуск и перезапуск, health/readiness. Performance/security/load — отдельно, по риску, не вместо функциональных тестов.

## Срез 4 — независимые CI lanes

Quick Checks #65 (46092285447): frozen install/api:check PASSED, 316 files, один formatter error в testcontainers.mjs; исправлен точно по логу, typecheck skipped. Новый CI сохраняет event triggers, permissions contents:read, concurrency, pinned Ubuntu/Node/pnpm/actions, frozen installs, все 20 прежних именованных проверок после общего setup и cleanup. Четыре независимых jobs: static (OpenAPI, lint, typecheck, unit), browser (полный build, Chromium, controlled E2E/axe), integration (filtered runtime build, Chromium, Compose PG/S3, migration, integration, client, smoke, auth-compat+real browser, cleanup), security (workspace audit, isolated npm install/audit, license policy по обоим деревьям). Отдельный job quality с always() и явным сравнением каждого needs.result с success. Только 1 из 256 комбинаций четырёх известных статусов удовлетворяет условию; проверка таблицы истинности статическая, не выполнение GitHub Actions. Job quality не выполняет фиктивные проверки, а агрегирует реальные обязательные результаты; branch protection не меняется. При глобальной отмене workflow возможна отмена самого quality, что не является success.

Trade-off: 4 независимых runner повторяют frozen install; два браузерных runner устанавливают Chromium, два runner собирают нужные приложения. Не передаём node_modules, .next или секреты между jobs, не включаем remote cache и не добавляем сторонние actions. Это осознанный первый вариант для независимых результатов и изоляции; суммарные runner-minutes могут вырасти. Измерить wall-clock, очередь и стоимость после первого полного запуска, затем рассмотреть безопасный pnpm store cache/артефакты только при доказанной экономии. Integration lane всё ещё последовательна внутри; ошибка в ней может остановить дальнейшие шаги, но не соседние jobs; cleanup всегда. Таймаут каждого рабочего job 20 минут, quality 5 минут. Quick Checks workflow без изменений. Источники: https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-jobs ; https://docs.github.com/en/actions/reference/workflows-and-actions/contexts ; https://docs.github.com/en/actions/reference/workflows-and-actions/expressions ; https://turborepo.dev/docs/reference/run . Полный CI ещё не выполнялся на новой архитектуре.

## Заключительное ревью — раздельные политики Admin/public
