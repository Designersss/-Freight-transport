# Integrations

Применять к bot, storage, email, внешним API и webhook. Использовать согласованные grammY, SeaweedFS/S3, существующие контракты и фоновые задачи; новые поставщики, библиотеки и платные сервисы только по отдельному согласованию.

- Адаптер изолирует внешний протокол, ошибки и конфигурацию; бизнес-правила и роль остаются в серверных сервисах. Проверять официальную документацию закреплённых версий и возможности реально развёрнутого сервиса, не полагаться на общую S3 совместимость.
- Telegram: один бот, валидировать источник webhook (если используется) и входные данные, дедупликация update ID там, где нужна, связывать identity безопасно через сервер, не доверять отображаемому имени/username. Проверять контекст пользователя/компании и локализацию; не раскрывать внутренние данные в чатах.
- Файлы: авторизовать upload/download/delete, ограничить размер и разрешённые форматы, генерировать непредсказуемые ключи без user path, частные объекты по умолчанию, короткоживущие URL по необходимости. Не считать MIME или расширение единственной проверкой. Не путать отсутствие объекта с отказом прав; проверять cleanup.
- Документировать ограничения внешнего сервиса, timeout, retry/backoff, idempotency, обработку 429/5xx, отказ и повторную обработку. Не повторять неидемпотентный вызов вслепую. Защищать webhook от replay, когда протокол это позволяет; не писать токены/подписанные URL/содержимое сообщений в логи.
- Использовать синтетические данные и изолированные окружения; smoke/integration с фактическим S3-совместимым хранилищем или тестовым ботом только при доступе и разрешении. Не отправлять реальные уведомления при CI. Проверить сбой и восстановление, а не только happy path.

Результат: контракт адаптера, модель доверия, обработка ошибок и повторов, проверка на реальном тестовом сервисе или явно отмеченный блокер.
Официальные источники: https://grammy.dev/ ; https://core.telegram.org/bots/api ; https://github.com/seaweedfs/seaweedfs ; https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html .
