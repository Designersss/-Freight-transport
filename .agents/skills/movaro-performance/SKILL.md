# Performance

Применять при медленной загрузке, больших списках, календаре, аналитике, изменении bundle и тяжёлых взаимодействиях. Сначала определить сценарий, окружение и измерение; не оптимизировать по впечатлению.

- Снять baseline на сопоставимом production build: загрузка/сеть, React Profiler или браузерный performance trace, размер JS, память и длительность конкретного действия по необходимости. Локальные lab-метрики не выдавать за реальные пользовательские Core Web Vitals.
- React: локализовать состояние, убрать ненужные вычисления/эффекты и каскадные обновления. Мемоизацию применять по доказанному bottleneck, а не оборачивать всё. Стабильные ключи; сохранять доступность и поведение.
- Next.js: не расширять client boundary без причины; избегать последовательных независимых запросов; параллелить только независимые операции и соблюдать rate limits. Стратегия кеша соответствует реальной версии, правам, компаниям и актуальности; не кешировать приватные данные общим ключом.
- Проверять тяжёлые зависимости и дублирование; динамически загружать действительно тяжёлые необязательные части там, где это не ухудшает UX. Не добавлять анализатор bundle без необходимости/согласования. Использовать локальные шрифты и подходящий Image, резервировать место для контента.
- Большие таблицы и списки: серверная фильтрация/пагинация, если это поддержано контрактом; виртуализация только при измеренной потребности и с клавиатурной доступностью. Календарь: ограничивать видимый диапазон запросов и сохранять корректность пересечений/часовых поясов. Не оптимизировать за счёт пропуска бизнес-проверок.
- Сравнить baseline и результат на одинаковых условиях; проверять LCP, INP, CLS там, где релевантно, и конкретные latency/рендеры. Не устанавливать произвольный бюджет как уже утверждённый; предложить целевой бюджет на основании измерений.
- После оптимизации повторить функциональные и доступные сценарии, проверить отрицательные эффекты, документировать trade-offs.

Результат: измерение до/после, методика, реальные данные и оставшиеся проблемы; если измерений нет — только гипотезы.
