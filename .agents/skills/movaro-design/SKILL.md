# MOVARO Design — рабочий процесс

Навык представляет собой собственные инструкции проекта, пригодные для чтения в ChatGPT и других агентах. Не требует установки CLI, MCP, бинарников, API-ключей или сетевого доступа в production.

## До реализации

1. Прочитать AGENTS.md, DESIGN.md, docs/design-system.md, docs/e2e.md и актуальный issue/PR. Установить границы задачи, роли, реальные данные и состояния. Прочитать действующие токены и используемые компоненты. Не считать старый скриншот точной спецификацией размеров.
2. Сопоставить новый экран с согласованным референсом: что сохраняем, что адаптируем под MOVARO и что не копируем. Если нет референса или точного значения — записать это, использовать существующую систему, не объявлять предположение решением владельца.
3. Проверить официальную документацию версий библиотек. Новые зависимости не являются целью дизайн-ревью.

## Реализация

4. Использовать общие компоненты и семантические токены. Сохранять API, права и реальные сценарии. Не менять соседние экраны вне задачи. Для общих примитивов проверить потребителей web/admin/Storybook.
5. Проверить основные и пограничные состояния. Особое внимание полям: видимый, но аккуратный focus-visible; локализованная ошибка; сохранение введённых данных при корректируемой ошибке; pending; корректный повторный submit. Не отключать обязательные серверные проверки.
6. Оценить визуальную иерархию, отступы, контраст, читаемость и отсутствие лишнего декора. Сравнить реальный результат с референсом, фиксировать отклонения и их причины. Исправлять функциональные дефекты раньше декоративных.

## Design Quality Gate

- Матрица: dark/light × RU/EN × desktop/mobile (существующий 375px viewport и desktop из apps/e2e; дополнительные узкие размеры при необходимости). Для затронутых состояний — ручная проверка/Playwright; отдельно указать, какие комбинации реально проверены.
- Клавиатура: Tab/Shift+Tab, Enter/Space по семантике, Escape в оверлеях, видимый фокус, отсутствие ловушек. Проверить масштабирование, overflow, длинные переводы, reduced motion при анимации. WCAG 2.2 AA как целевой стандарт; axe не доказывает полное соответствие.
- Для изменённых компонентов добавить/актуализировать Storybook stories и целевые тесты, для бизнес-сценариев — E2E с изолированными тестовыми данными. Для визуальных регрессий использовать существующий Playwright: скриншоты либо toHaveScreenshot для стабильного согласованного baseline. Не обновлять baseline вслепую; исключать секреты/персональные данные; не отключать проверки ради прохождения CI. При различии платформ фиксировать окружение.
- Проверки согласно AGENTS.md и docs/e2e.md: pnpm install --frozen-lockfile, pnpm check, pnpm licenses:check, pnpm e2e:install, pnpm test:e2e; применимые интеграционные проверки и обязательный quality CI. Не заявлять успешный запуск без результата.
- PR: список затронутых экранов, issue, источник решений, скриншоты/результаты по матрице, отклонения, непройденные проверки, ссылки на тесты и CI. Ручная приёмка владельца обязательна. Если браузер/данные недоступны, gate остаётся открытым.

## Первая область применения: RD-04 / #5

Для открытого PR #24 по авторизации проверить общие поля, ошибки, состояния отправки, адаптивность и локализацию. Вопросы подтверждения почты, пароля и серверного входа — самостоятельные функциональные требования #5, не решаются данным документационным PR. Результаты аудита записывать только после просмотра актуальных экранов и ветки.
