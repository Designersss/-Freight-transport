# MOVARO Code Style

## Обязательный вход в задачу

Прочитать этот SKILL.md и AGENTS.md при каждом взаимодействии с проектом, включая анализ без изменения файлов, документацию, ревью, диагностику и merge. Если утверждённые инструкции ещё не попали в рабочую ветку, прочитать их из согласованного ref и указать источник. Для изменения кода прочитать актуальные biome.json, .editorconfig, package.json, lockfile в релевантной части, tsconfig соответствующего workspace и ближайшие уже принятые примеры. Источник истины — действующая конфигурация и закреплённые версии, а не память или универсальный стиль другого проекта.

## Базовое форматирование

- UTF-8, LF, два пробела, без табуляции и хвостовых пробелов, один завершающий перенос строки. Проверять правила .editorconfig и специальные настройки формата.
- Biome закреплён в корневом package.json; на 27.11.2026 это 2.6.8. Использовать локальную версию через pnpm exec, не npx latest и не другой форматтер.
- JS/TS: двойные кавычки для строк, точки с запятой, многострочные конструкции и завершающие запятые по выводу Biome. Не ломать длинную строку ради произвольного лимита; ориентироваться на форматтер (например, классы Tailwind).
- JSON: двойные кавычки, без комментариев и завершающих запятых. CSS: существующие токены, формат Biome и поддержка Tailwind directives. YAML: два пробела, корректное экранирование строк, без изменения семантики GitHub Actions.
- Не форматировать вручную сгенерированный OpenAPI/client или Prisma client; использовать существующие генераторы. Не менять исключения biome.json, .gitignore или логику генерации ради прохождения CI.
- В Markdown выравнивать колонки таблиц по фактическому выводу Biome, не оставлять хвостовые пробелы, разделять блоки пустыми строками. Для всех SKILL.md обязательна пустая строка сразу после первого разделителя из трёх дефисов, затем YAML name и description, закрывающий разделитель и пустая строка перед заголовком. Description со специальными символами YAML заключать в кавычки. Name совпадает с именем каталога. Это проверенный формат коммита b497eb8 и CI 45969557349; не добавлять ради него override.
- Код и идентификаторы на английском, документация и Issues на русском, пользовательские строки RU/EN через локализацию. Комментарии поясняют причину и инварианты, а не очевидное действие.

## TypeScript и импорты

- TypeScript 5.9.3 на момент фиксации. Общий tsconfig задаёт strict, noUncheckedIndexedAccess, exactOptionalPropertyTypes, noImplicitOverride, noFallthroughCasesInSwitch, noUnusedLocals, noUnusedParameters, verbatimModuleSyntax и forceConsistentCasingInFileNames; сверять актуальные настройки workspace. Не отключать проверки.
- Обрабатывать unknown, nullable и потенциально отсутствующие элементы массивов/словарей явно. Не использовать any, небезопасные assertions, non-null assertion или ts-ignore для обхода проверок. Не передавать undefined в optional property, если тип этого не допускает; при необходимости условно включать свойство. Удалять неиспользуемые импорты, переменные и параметры; обязательные сигнатуры обрабатывать согласно текущим правилам.
- Использовать import type для импортов только типов, inline type для смешанных импортов по принятым примерам и organize imports Biome. Не переводить runtime DI-токен NestJS в type-only import. Для NodeNext ESM относительные импорты с расширением .js, как в apps/api; для Next.js с Bundler resolution следовать существующим импортам workspace. Не менять moduleResolution ради ошибки импорта.
- Файлы модулей по существующим именам, например health.controller.ts, database.service.ts, button.tsx, api-config.test.ts; классы и React-компоненты PascalCase, функции/переменные camelCase. Публичные экспорты и package boundaries сохранять; не создавать новые aliases без причины.
- SOLID, KISS, DRY; использовать типы и общие функции, а не дублировать код. Контроллеры тонкие, React-компоненты функциональные, чистые вычисления отдельно. Для деталей применять профильные навыки.

## Проверки до отправки изменений

- Перед редактированием определить scope и проверить исходный статус, версии Node/pnpm по .nvmrc и package.json, доступность локальных зависимостей. Не перезаписывать изменения владельца.
- После написания запускать закреплённый formatter для изменённых файлов: pnpm exec biome format --write с точным перечнем поддерживаемых путей. Затем pnpm exec biome check с тем же перечнем и pnpm lint для всего репозитория. При необходимости использовать безопасные исправления pnpm exec biome check --write только для затронутых файлов и проверить весь diff. Не применять --unsafe, не добавлять ignore и не ослаблять правила для прохождения.
- При изменении TS/TSX, зависимостей или конфигурации типов выполнить pnpm typecheck; при изменении поведения выполнить применимые тесты. Полный локальный набор pnpm check запускает lint, typecheck, test, build. API, лицензии, E2E, integration, stack и прочие проверки по текущему CI и области изменения. Перед коммитом проверить git diff --check, git diff и список файлов; не коммитить артефакты, секреты и несвязанные форматирования.
- При отсутствии окружения, pnpm, сети или нужной версии Biome не утверждать успешный локальный запуск. Сверить статически исходные настройки и принятую форму, описать блокер, отправить только в рабочую ветку/Draft PR, если это нужно для реальной проверки, и проверить обязательный quality CI на новом head. Не считать проверку пройденной до подтверждения. Не использовать CI как замену доступным локальным проверкам.
- В итоговом отчёте всегда указать прочтение movaro-code-style, актуальный ref, команды и фактические результаты или причину отсутствия локального запуска. При падении CI прочитать полный лог нужного шага, исправить причину, повторить проверки. Не мержить до зелёного CI и разрешения владельца.
