# MOVARO — дизайн-контракт

Статус: предлагаемое дополнение RD-03.1 к [существующей дизайн-системе](docs/design-system.md). Основание: #4, #5, утверждённые требования владельца и код принятого RD-03 (2993e3f). Точные финальные оттенки и размеры — по ручной приёмке, не считаются автоматически утверждёнными. Источник реализованных токенов: [packages/ui/src/styles.css](packages/ui/src/styles.css).

## 1. Визуальный характер

Рабочий интерфейс аренды и управления спецтехникой: спокойный, компактный, тёмный по умолчанию, ясная иерархия, умеренная глубина. Приоритет — быстро понять состояние работы и выполнить действие. Не превращать кабинеты в промо-лендинг. Светлая тема обязательна. Сохранять согласованные референсы как направление, не копировать чужие логотипы, данные или экран целиком.

## 2. Цвет

Использовать семантические переменные общей UI-библиотеки: background, foreground, card, muted, border, primary, ring, destructive и соответствующие foreground. Кобальтовый акцент — для основных действий и значимых состояний, не для украшения каждой карточки. Текущие фон/акцент: dark #11141b / #829aff, light #f3f5f9 / #3159d7; это значения кода, не новые утверждённые цвета. Новые цвета только через общую систему и ревью. Статус не должен зависеть исключительно от цвета.

## 3. Типографика

Manrope локально; базовые размеры из RD-03: 13/12 px, заголовки 24–28 px, Lucide 16 px. Сохранять читаемость и масштабирование, не уменьшать текст ради вместимости. Даты, ставки, время и денежные значения форматировать по локали; при сравнении чисел использовать табличные цифры, если шрифт поддерживает.

## 4. Отступы и сетка

Компактные, повторяемые интервалы. Использовать текущие компоненты и шкалу Tailwind; избегать случайных значений и вложенных карточек без смысловой причины. Радиусы карточек 12–16 px, контролов 8–12 px (целевое направление RD-03, расхождения с кодом фиксировать отдельно). Плотность не должна ухудшать доступность интерактивных целей.

## 5. Компоновка

Общие Header, Sidebar, AppShell, PageLayout; не создавать отдельную визуальную систему для admin. Сохранять ролевые ограничения. Сначала главное действие и данные, затем второстепенное. Таблицы — семантические, с читаемыми заголовками, предсказуемыми действиями, пустыми состояниями и контролируемым overflow. На мобильном перестраивать структуру, а не только уменьшать шрифты. Не выдумывать бизнес-данные или маршруты.

## 6. Компоненты и формы

Переиспользовать packages/ui и shadcn/Radix. Новые варианты только при реальной потребности; не дублировать Button, Input, Field, Alert и другие примитивы. Подписи связаны с полями, ошибки локализованы, aria-invalid/aria-describedby корректны. Никаких двух одновременно нарисованных focus-обводок; предложенный тонкий focus-индикатор проверять на контрасте и клавиатуре, не удалять его без замены. Состояния default, hover, focus-visible, active, disabled, pending, invalid, empty, error и success — по применимости. Ошибки и pending не скрывают результат действия, повторная отправка контролируется. Сервер является источником истины для прав и валидации. Не изменять бизнес-логику ради вида.

## 7. Движение и взаимодействие

Микроанимации только для обратной связи и ориентации; без задержки действий. Учитывать prefers-reduced-motion. Hover не является единственным способом доступа к действию. Escape, Tab, видимый фокус и возврат фокуса для оверлеев — согласно семантике компонента. Проверять touch без зависания hover.

## 8. Язык и бренд

MOVARO, без изменения технического namespace @freight. RU/EN через next-intl, без новых захардкоженных пользовательских строк. Короткие конкретные подписи, ясные ошибки и дальнейшие действия. Не обещать неподдерживаемые функции. Название утверждено, фирменный знак отдельно согласуется.

## 9. Антипаттерны

Не вводить градиенты, свечение, декоративные бейджи, случайные тени, разные радиусы и крупные маркетинговые заголовки без обоснованного согласования. Не убирать доступный фокус ради минимализма. Не использовать мок-данные в production, не скрывать ошибки, не обходить проверку email или права. Не переопределять тему на уровне страницы без необходимости.
